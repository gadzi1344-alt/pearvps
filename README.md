# Pear — версия для VPS

Социальная сеть Pear на основе исходного проекта. Страница входа обновлена: вход и регистрация через Google или GitHub; отдельной формы почты/пароля, Discord и номера Pear в интерфейсе больше нет. Подарки, виртуальный баланс и валюта Pear из приложения удалены. При первом успешном входе через провайдера может создаться новый аккаунт. Существующий профиль не переносится автоматически на другую учётную запись.

## Важно про существующую базу

Эта сборка НЕ подключена к вашей базе и НЕ меняет её. Ей нужна база Supabase с таблицами, политиками RLS, Storage и функциями, совместимыми с исходным проектом Pear. Старые SQL-файлы сохранены в `docs-original/` только для справки. **Не запускайте их повторно на существующей базе** без проверки и резервной копии. Старые данные и таблицы номеров, подарков и баланса в Supabase не удаляются и могут продолжать существовать в базе. Если их нужно полностью отключить или удалить в базе, это следует сделать отдельно после проверки зависимостей и создания резервной копии.

Если раньше вы входили только по номеру Pear или через Discord, после перехода вы можете потерять доступ к старому аккаунту: Google/GitHub не обязательно привяжутся к нему автоматически. Сначала проверьте, есть ли у этих пользователей уже привязанный Google/GitHub, и сделайте резервную копию базы. Не отключайте работающий старый сайт, пока не проверите вход и данные на тестовой копии.

## Загрузить в GitHub

1. Распакуйте ZIP на компьютере. Создайте новый **пустой** репозиторий GitHub.
2. Загрузите в корень репозитория содержимое папки проекта, включая скрытый `.gitignore`. Не загружайте `.env`, пароли, ключ `service_role` или `sb_secret`.
3. Изображения, исходный код и пример службы уже входят в архив.

## Supabase и OAuth

1. В настройках вашего Supabase найдите Project URL и **публичный** publishable key (`sb_publishable_…`) или старый anon key. Не присылайте и не публикуйте `service_role` / `sb_secret`.
2. В Supabase Authentication → Sign In / Providers включите Google и GitHub и настройте каждого провайдера, если это ещё не сделано. На стороне Google/GitHub нужен OAuth callback URL, который указан Supabase для соответствующего провайдера; адреса сайта добавляются отдельно в настройках Redirect URLs Supabase.
3. В Authentication → URL Configuration добавьте адрес сайта с `/` в конце в список разрешённых Redirect URLs. Для проверки через SSH-туннель это будет `http://127.0.0.1:3000/`. Если проект Supabase уже используется старым сайтом, не меняйте его Site URL необдуманно — это может повлиять на существующие ссылки. OAuth на публичном сайте рекомендуется настраивать после появления HTTPS-адреса.
4. Ключ и URL задаются **на сервере**, а не в GitHub. Публичный ключ также выдаётся приложению в браузере — права на данные должны быть ограничены настройками RLS и Storage Supabase.

## Проверка на Ubuntu (Node.js 20 или новее)

После установки Node.js и Git проверьте версии: `node --version` и `git --version`. На VPS клонируйте свой новый репозиторий, заменив ссылку на свою:

```bash
git clone https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git pear
cd pear
export SUPABASE_URL='https://YOUR_PROJECT.supabase.co'
export SUPABASE_ANON_KEY='ВАШ_ПУБЛИЧНЫЙ_ANON_ИЛИ_PUBLISHABLE_KEY'
node server.js
```

Сам сервер не требует `npm install`. Однако Supabase JS загружается браузером с esm.sh, поэтому у посетителя должен быть интернет-доступ к CDN. Для постоянной работы используйте службу ниже вместо `export`. Тестовый сервер по умолчанию слушает только `127.0.0.1:3000` на VPS. Чтобы открыть его у себя без домена, настройте в Termius Local Port Forward: локальный порт `3000` → VPS → `127.0.0.1:3000`, включите туннель и откройте **на своём компьютере** http://127.0.0.1:3000/. Закрытие Termius отключит туннель, но не службу systemd.

## Автозапуск через systemd

Пример `deploy/pear.service` предполагает файлы в `/opt/pear`, системного пользователя `pear`, Node по пути `/usr/bin/node` и файл настроек `/etc/pear/pear.env`. Не запускайте его до проверки этих условий. После размещения файлов (включая скрытые) и настройки прав можно выполнить от root:

```bash
id pear >/dev/null 2>&1 || useradd --system --user-group --home-dir /opt/pear --shell /usr/sbin/nologin pear
chown -R pear:pear /opt/pear
install -d -m 700 /etc/pear
nano /etc/pear/pear.env
```

В `pear.env` впишите свои значения без кавычек и сохраните:

```text
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=ваш_публичный_ключ
HOST=127.0.0.1
PORT=3000
```

```bash
chmod 600 /etc/pear/pear.env
cp /opt/pear/deploy/pear.service /etc/systemd/system/pear.service
systemctl daemon-reload
systemctl enable --now pear.service
systemctl status pear.service --no-pager
journalctl -u pear.service -n 50 --no-pager
```

Перезапуск после изменения настроек: `systemctl restart pear.service`. Если `which node` не показывает `/usr/bin/node`, измените путь `ExecStart` в службе перед её запуском. Не запускайте одновременно пробный `node server.js` и службу на одном порту.

Для публичного доступа нужен обратный прокси с HTTPS и подходящий адрес/сертификат; не открывайте приложение или админские секреты в интернет по незащищённому HTTP. Настройку сделаем отдельно, когда будет выбран адрес.

## Удаление аккаунта

По умолчанию сервер отвечает, что удаление не настроено. Исходный обработчик сохранён и требует серверный `SUPABASE_SERVICE_ROLE_KEY`. Он имеет высокие привилегии: его нельзя отправлять в браузер или GitHub. Перед включением отдельно проверьте права, бэкап и совместимость. Удаление может затронуть данные и Storage.
