# Обновление Pear: модерация

## Что изменено

- Администратор назначает и снимает модераторов в админке: три нажатия на свою кнопку «Профиль», поиск пользователя, «Назначить модератором».
- Модератор заходит так же — три быстрых нажатия на свою кнопку «Профиль». Видит жалобы, отмечает их рассмотренными и может удалить пожалованный пост после рассмотрения. Перед удалением есть подтверждение. Назначать модераторов, управлять галочками и просматривать админ-статистику модератор не может.
- Пользовательская синяя и зелёная верификация остаётся в базе; пока действует роль модератора, отображается его третий значок и подпись «Модератор проекта Pear». При снятии роли восстанавливается прежняя галочка, если была. Значок берётся из `assets/verified-moderator.png`.
- Список модераторов виден всем вошедшим пользователям, чтобы показывать значки. При удалении поста связанные жалобы удаляются каскадно; изображение попадает в очередь очистки. Публикацию нельзя восстановить через панель.

## Перед установкой

Сделайте резервную копию Supabase. SQL предназначен для существующей схемы именно этого проекта и изменяет политики и функции обработки жалоб. Если вы меняли эти функции самостоятельно или есть другие политики, сначала проверьте совместимость и безопасность; новый скрипт не удаляет ранее созданные политики. Не запускайте другие SQL из `docs-original` повторно. Проверьте обновление на тестовой базе и тестовых аккаунтах до применения на рабочей.

1. Откройте свой Supabase → SQL Editor. Убедитесь, что выбран нужный проект. Откройте файл `12-moderators.sql`, скопируйте и выполните его целиком. Скрипт рассчитан на однократное применение; если он сообщил об ошибке, не продолжайте — сохраните её текст. Транзакция отменяет изменения при ошибке.
2. В репозиторий загрузите изменённые `app.js`, `style.css` и `assets/verified-moderator.png`, а также папку `update`. Не загружайте `.env` и секреты. SQL должен быть применён до обновления сайта.
3. На VPS обновите существующий репозиторий из папки `/opt/pear`. Если есть локальные изменения, `git pull` может отказать: сначала проверьте `git status`, не удаляйте свои изменения. Так как файлы принадлежат системному пользователю `pear`, удобнее выполнить `sudo -u pear git -C /opt/pear pull --ff-only`.
4. Перезапустите `systemctl restart pear.service`; проверьте `systemctl status pear.service --no-pager`. Обновите страницу браузера. Nginx и настройки ключей менять не нужно.
5. Зайдите существующим администратором. Назначьте тестового модератора, войдите под ним и проверьте отображение значка, тройное нажатие, жалобу и удаление тестового поста. Проверьте, что обычный пользователь не видит жалобы и не может назначить роль, а модератор не может назначить другого модератора. После снятия роли подтвердите, что доступ исчез. При ошибках не публикуйте обновление до исправления.

Фактические права определяются Supabase, а не скрытой кнопкой. Только аккаунт, уже записанный в `pear_admins`, может назначать модераторов. Выполнение SQL и безопасность существующих кастомных политик в вашем проекте проверить из этого архива невозможно.
